# Codebook

All files are UTF-8 (with BOM), comma-separated. They are generated by `../tools/make_data_package.py`
from the structured paper write-ups (`../tools/data/writeups.json`) and the bibliography of the article.

## extraction_table.csv (one row per included work, 180 rows)

| Column | Definition |
|---|---|
| Study | First author (and second author, or et al.) with year; the full reference is in refs.bib of the article. |
| Key | Citation key in refs.bib. |
| Topic | Section of the review the work is synthesised in: LLM planners and orchestrators; VLA and robot foundation models; Perception and epistemic uncertainty; Reinforcement learning and policy variance; Imitation learning and behavioral fidelity; Fault detection, adaptation and recovery; Meta-learning; Uncertainty fusion and calibration; On-device adaptation and continual learning; Adaptive computation, mixture of experts and routing; Platforms, benchmarks and evaluation; Safe learning. |
| Role | Core (bears directly on orchestration, a confidence signal or the edge constraint); Standard (established method that a component would be built on); Review. |
| Evidence level | E1 conceptual (position or proposal without an algorithm or experiments); E2 algorithmic or analytic (algorithm or theory with analytic or toy evaluation); E3 simulation or benchmark; E4 real robot, laboratory; E5 real robot, extensive (many trials, several platforms or long runs); E6 deployment with real users; R review or tutorial; S software, dataset or benchmark suite. |
| Source stream | Initial list (stage 1) or Structured search (stage 2); see search_strings.md. |
| Publication status | Journal article; Conference paper; Preprint (arXiv only at the time of the search). |
| Basis | Full text, Abstract (abstract and publisher or arXiv page) or Standard reference (well-known work summarised from its standard description; to be checked against the full text). |
| Task, Method, Setup and data, Key result, Limitation | Extracted as reported. "Not given in the abstract" marks numbers that must be taken from the full text. |
| Edge footprint (as published) | Compute needed by the system as evaluated, relative to a Raspberry-Pi-class robot. |
| Edge class | Inference platform as published, hand-coded from the previous column: Pi-class or embedded CPU; Embedded GPU (Jetson class); Workstation GPU (desktop, laptop or single consumer GPU); Datacenter or cloud (TPU pods, GPU clusters or cloud model APIs); Not stated. Training cost is not coded. |
| Confidence signal class | Confidence or reliability signal the work provides or uses, hand-coded: Conformal or calibrated; Epistemic uncertainty (ensembles, dropout, evidential, Bayesian or posterior); Failure, anomaly or novelty score; Policy variance or entropy; Routing score or predicted quality (gate scores, value or quality predictions used to choose among options); None. |
| Role in the framework | How the work serves the orchestration framework of the review (baseline, component, confidence signal, competitor, evaluation reference). |
| Also in companion survey | Survey 1 or Survey 2 if the same work is cited there (title match); No otherwise. |
| DOI or identifier | DOI link, or arXiv link when no DOI is recorded. |

## quality_appraisal.csv (161 rows: all works at levels E2–E5)

| Column | Definition and coding rule |
|---|---|
| Q1 Method specification | M: method described in at least 12 words of the method field; P: shorter description; N: none. |
| Q2 Baseline comparison | M: comparison with a named baseline or prior method with a number; P: comparison without a number; N: no comparison reported; ?: abstract gives no results. |
| Q3 Physical validation | M: E5, or E4 with physical robot or hardware stated in the setup; P: E4 otherwise, or E2–E3 with a real-robot component mentioned; N: simulation, benchmark or analysis only. |
| Q4 Compute reporting | M: latency, memory, parameter count, FLOPs or a stated compute, memory or cost reduction given as a number; P: compute, latency or efficiency discussed without a number; N: not reported. |
| Q5 Quantitative evaluation | M: numerical result reported; P: qualitative result only; ?: abstract gives no numbers. |
| Q6 Code or model release | M: release of code, models or weights stated; ?: not stated in the material read (abstracts rarely state it, so ? is not a negative judgement). |
| Q7 Confidence signal | M: exposes a calibrated, epistemic, failure or policy-variance signal (classes C, E, F, V); P: exposes a routing score or predicted quality (class Q); N: none. |

Codes: M met; P partly met; N not met; ? not assessable without the full text. Q1–Q6 are coded by the
rules above from the extraction fields; Q7 follows the hand-coded signal class. Reviews (R) and
software (S) are not appraised. Rule-based codes are a first pass for confirmation against the full texts;
any code changed during that confirmation should be recorded in the file with the reason.

## study_summaries.csv (180 rows)

| Column | Definition |
|---|---|
| Key | Citation key in refs.bib |
| Study | Author(s) and year |
| Topic | As in the extraction table |
| Evidence level | As in the extraction table |
| Basis | Full text, Abstract or Standard reference |
| Summary | Plain-text summary (problem, method, setup, main result, limitation, relevance to the framework) |
| Summary_keyed | The same text with cited works marked `[CITE:key]`, used to typeset Section S5 of the supplementary material |
| Verification_note | Bibliographic or content details still to be confirmed against the publisher record or full text; empty if none |
